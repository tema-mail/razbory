# Supabase – сервер с базой, входом и файлами в аренду. Для планёрки годится, для клиентских данных – нет

Supabase избавляет от своего сервера: база, вход по паролю, хранилище файлов и обновление у всех на экране сразу уже готовы. Планёрка живёт на бесплатном тарифе и платить не нужно. Ограничения: компания американская, данные лежат за рубежом, бесплатный проект засыпает после недели без входов, резервных копий на бесплатном тарифе нет.

## 1. Что это такое и что там можно делать

Обычный сайт – это страницы. Как только нужно что-то **хранить и пускать по паролю** (задачи, заявки, файлы, кабинет), нужен сервер с базой. Supabase даёт такой сервер готовым:

| Что | Простыми словами | Пример у нас |
|---|---|---|
| База (Postgres) | таблицы с данными, как Excel, только для программ | задачи и проекты планёрки |
| Вход (Auth) | пароль, письмо со ссылкой, вход через Google, GitHub, по телефону | общий пароль студии |
| Права (RLS) | сама база решает, кому что можно читать и менять | без пароля планёрка ничего не отдаёт |
| Хранилище (Storage) | файлы и картинки, закрытые или открытые | скриншоты в комментариях, до 20 МБ |
| Живое обновление (Realtime) | изменил один – у всех на экране сразу | задача сдвинулась у всей команды |
| Функции (Edge Functions) | свой код на их сервере: оплата, письма, обращение к ИИ | пока не пользуемся |
| Готовый API | к таблицам сразу можно обращаться со страницы, писать сервер не надо | так и работает планёрка |
| Векторы, расписание, очереди | поиск по смыслу для ИИ, задачи по таймеру | пока не пользуемся |

Главная выгода: страница может быть простым HTML без сервера, а данные, вход и права держит Supabase.

## 2. Как устроена наша планёрка

- Одна таблица `docs`: раздел (проекты, задачи, команда, время, комментарии), номер записи и сами данные.
- Один пользователь `studio@example.com` с общим паролем на всю студию, раздельных входов нет.
- Хранилище `files` для вложений, закрытое: без входа файлы не открыть.
- Включено живое обновление: правки видны сразу во всех открытых вкладках.
- Проект `dnehefuakwacgrmdnezl` в организации Deford2027, тариф **Free**. Последний вход – 14.11 в 03:06.
- Сам сайт планёрки теперь на нашем московском сервере, а данные остаются в Supabase. Из Москвы он отвечает: проверено 15.11, ответ за 0,47 с.

## 4. Где Supabase нам не подходит

- **Оплата.** Pro платится иностранной картой. Российская не пройдёт, только через посредников.
- **Закон.** По 152-ФЗ персональные данные россиян (заявки, телефоны, клиенты) должны сначала записываться в базу в России. Supabase – не Россия. Поэтому заявки клиентов и ЛК сайтов держим на своём сервере, как уже делаем у EV Sibir, Автобалла и магазинов.
- **Доступ из РФ не гарантирован.** Сервис иностранный: у части провайдеров может не открываться, и повлиять на это мы не можем.
- **Засыпание.** На Free проект встаёт после недели без обращений. Будит кнопка Restore, данные целы.
- **Нет копий.** На Free резервных копий нет: удалили – значит, удалили. Для планёрки стоит раз в сутки выгружать базу к нам.

## 5. Что вместо

- **Оставить как есть** для внутренних инструментов без клиентских данных: планёрка, черновые прототипы. Бесплатно и без своего сервера.
- **Свой Postgres или SQLite на московском сервере** для всего, где есть клиенты и заявки. Мы так уже работаем.
- **Supabase на своём сервере.** Он открытый, ставится в Docker, но тяжёлый: ему нужно 2–4 ГБ памяти, а на московском сервере 3,8 ГБ на всё. Без отдельного сервера не советую.

## Нужно от тебя

1. В открытой вкладке SQL Editor нажми Cmd+V, затем зелёную **Run**. Запрос задаст новый пароль планёрки, он уже сохранён у меня на маке. Напиши «готово» – я проверю вход и пришлю пароль.
2. Скажи, нужна ли ежедневная копия планёрки на наш сервер.
