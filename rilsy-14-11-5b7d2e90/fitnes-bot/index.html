Фитнес-тренер в Telegram: что взять готовым

Послушать итог голосом

Готового бота «фото еды + вес + замеры + тренировки» на русском с большим сообществом нет: берём за основу небольшой русский бот SnapCaloriesAI (фото → КБЖУ, Gemini или любой OpenAI-совместимый ключ, то есть OpenRouter), дописываем вес, замеры и журнал тренировок, граммовку подтверждаем кнопками или весами. Тяжёлые трекеры (wger, SparkyFitness, NutriTrace) – вариант хранилища позже, не для MVP.

Откуда задача: не из рилсов – Артём 14.11.2026: «фитнес-тренер в боте, который считал бы мой прогресс и, очень важно, что я ем: скидываю фото, он распознаёт». Только чтение: звёзды, коммиты и лицензии через gh api 14.11.2026, ничего не ставили.

3. Базы продуктов и как получить граммовку

Базы

База Русское Доступ Проверено
Open Food Facts 37 488 товаров с рынка РФ, из них 17 847 с заполненной пищевой ценностью; Беларусь 1 798; всего 4 913 311 (API 14.11.2026) бесплатный JSON API по штрихкоду, ежедневные дампы; массовый парсинг API блокируют – брать дамп да, api/v2/search?countries_tags_en=russia
USDA FoodData Central нет, английский; зато сырые продукты и блюда очень подробно бесплатный API-ключ страница API 200
wger ingredient продукты из OFF, есть русские названия (API показывает ровно 1 000 – похоже на потолок выборки) REST да
Русские таблицы (Скурихин, calorizator и т.п.) есть, но открытой базы с API не нашёл только сайты и книги; парсить сайты – юридический риск поиск GitHub и веба – пусто

Практика: штрихкод или фото этикетки → OFF или чтение этикетки моделью (точно); готовое блюдо по фото → модель сама знает КБЖУ на 100 г для «борща» или «гречки с курицей» (как в SnapCaloriesAI и Adialia1); проверка цифр по USDA – опционально.

Как бот получает граммы по фото

Подход Где применяется Точность
Модель оценивает вес «на глаз», рядом вилка, ладонь, тарелка все боты выше ошибка ~35 % по весу и калориям, большие порции занижает
Модель предлагает граммы → человек подтверждает или правит кнопками DimaPhil, whats-my-calorie, CalTrack зависит от человека, обычно заметно лучше
Кухонные весы: вес вводит человек, модель только узнаёт блюдо – по исследованию ODU ошибка падает с 56,6 % до 20,2 %
Штрихкод / этикетка jasontan89, Adialia1 почти точно (данные производителя)
Глубина (RGB-D, LiDAR) Nutrition5k, calbro лучше «на глаз», но в Telegram-фото глубины нет
Своя библиотека частых блюд («мой обычный завтрак») DimaPhil точно после первого взвешивания

Исследования точности (с цифрами)

Работа Что мерили Главное
Fridolfsson и др., Current Developments in Nutrition, 09.2025, PMC12513282 GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro; 52 стандартных фото с тарелкой 24,3 см и приборами MAPE энергии: GPT-4o 35,8 %, Claude 35,8 %, Gemini 64,2 %; вес 36,3 / 37,3 / 65,0 %; белок ~61 % у обеих лучших. «Все модели систематически занижают, тем сильнее, чем больше порция». Вывод авторов: для точного учёта у спортсменов пока не годятся
Coburn и др., arXiv 2507.07048, 2025 8 моделей (GPT-4o, GPT-4.1, Claude 3.7 Sonnet, Gemini 2.5 Pro, Qwen2.5-VL и др.) на 806 реальных фото подсказка «время приёма пищи, место, что за блюдо» снижает ошибку в среднем на ~76 ккал; среднее MAE с цепочкой рассуждений ~255 ккал, MAPE ~37 %
Mu, Sun, He, ACM BCB 2025, ODU Nutrition5k + фото с телефона если дать модели настоящий вес: MAPE Gemini 2.5 Flash 56,6 % → 20,2 %, GPT-4.1 – 26,8 %. Граммы – главный источник ошибки
Nakagawa, Yamamoto, Nutrients 18(12):2017, 06.2026, doi 10.3390/nu18122017 Claude Haiku 4.5, Sonnet 4.6, Opus 4.6 лучшая цена/качество – Sonnet; промпт «не читай текст на фото, оценивай визуально» помогает только сильной модели
Nutrition5k, Google, CVPR 2021, arXiv 2103.03375, репо (417 ★) 5 006 тарелок из столовых Google, видео + RGB-D + взвешенные ингредиенты эталонный датасет для проверки; для бота не нужен, разве что для своего теста

Чем распознавать: цена за фото

Цены OpenRouter API на 14.11.2026 (Claude сверены с прайсом Anthropic). Допущение на одно фото: вход ~2 600 токенов (картинка ~1 100 + промпт ~1 500), выход ~500. У Claude картинка ≈ ширина×высота/750 токенов, при 1024 px по длинной стороне ~1 000–1 400. Цифры – оценка, не замер.

Итог по модели: на одного человека любая модель стоит копейки (до $2 в месяц), маленький лимит OpenRouter не помеха. Выбирать по точности на своих блюдах: прогнать 20 взвешенных приёмов пищи через Haiku 5.5, Sonnet 5.5 и Gemini 2.5 Flash, взять лучшую по ошибке. Ожидание: Sonnet 5.5 основной, Haiku 5.5 – если разница мала.

4. Рекомендация

Основа: форк SnapCaloriesAI (русский, aiogram, Docker, OpenAI-совместимый провайдер = OpenRouter, промпты отдельными файлами). Подсмотреть: подтверждение граммов кнопками (DimaPhil), правку по компонентам (whats-my-calorie), штрихкод через OFF (jasontan89).

Архитектура: 1. Telegram → бот на aiogram в Docker на claude-vps (Нидерланды: Telegram и API моделей доступны), пускает только ID Артёма. 2. Фото → модель через OpenRouter (Sonnet 5.5 или Haiku 5.5) → JSON: блюда, граммы, КБЖУ на 100 г, уверенность. 3. Кнопки «верно / изменить граммы / это другое» → запись; штрихкод или этикетка → Open Food Facts. 4. Команды /ves, /zamery, /trenirovka (упражнение, подходы, вес) → те же SQLite-таблицы. 5. Цель (сушка/масса) → норма ккал и БЖУ по Миффлину-Сан Жеору, через 2–3 недели поправка по реальному весу (адаптивный TDEE). 6. Каждый вечер итог дня, по воскресеньям неделя: вес-тренд, средние ккал и белок, тренировки, советы. 7. Позже, если нужно: выгрузка в wger или SparkyFitness ради графиков и синка часов.

MVP и часы (оценка):

Шаг Часы
Форк, запуск на claude-vps через OpenRouter, один пользователь, проверка на 5 фото 3–4
Русский промпт под наши блюда, подтверждение граммов кнопками, штрихкод OFF 5–6
Вес, замеры, журнал тренировок + графики 6–8
Цель, норма, итог дня и недели 3–4
Тест точности: 20 взвешенных приёмов пищи × 3 модели, выбор модели 3
Итого ~20–25 ч (с нуля было бы 40–60)

Риски: - Точность порций: ошибка ~35 %, большие порции занижает, масло и соусы не видно. Лечится весами, кнопкой правки граммов и библиотекой своих блюд. - Медицина: бот не врач; при болезнях (диабет, почки, ЖКТ) нормы только с врачом; не опускать калории ниже базового обмена; в боте – короткая оговорка один раз. - Лицензии: у SnapCaloriesAI «MIT» только в README, файла нет – для себя ок, для продукта клиентам спросить автора; wger и NutriTrace – AGPL (при раздаче как сервиса надо открывать код); SparkyFitness – только некоммерческое. - Код ботов – пет-проекты (0–4 ★): поддержки нет, чинить самим. - Данные о здоровье и фото – держать на своём сервере, ключ OpenRouter не светить, белый список ID обязателен.

5. Нужно от тебя: вопросы (без них не начать)

  1. Цель и срок: сушка, масса или рекомпозиция? Рост, вес, возраст, активность – для нормы.
  2. Есть кухонные весы и готов взвешивать хотя бы первые 2 недели? Без них точность ±35 %.
  3. Есть часы, браслет или умные весы (Apple Health, Garmin, Xiaomi)? Подтягивать шаги и вес сами или вводить руками?
  4. Тренировки: зал, дом, бег? Бот только ведёт журнал или ещё составляет программу?
  5. Только для себя или потом для клиентов и команды? От этого лицензии и архитектура.
  6. Отдельный бот или встроить в Еву (@Eva_Project_Deford_bot)? И какой ключ для модели: OpenRouter (какой лимит в $) или Claude на сервере?
