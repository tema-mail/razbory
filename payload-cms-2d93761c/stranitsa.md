# Payload CMS против нашего стека: что даёт и где пригодится заводу

Payload не лучше нашего стека целиком: в 4 из 15 пунктов он сильнее, в 9 сильнее мы, в 2 ничья. Payload выигрывает там, где клиент сам ведёт много контента: готовая админка с черновиками, версиями, медиатекой и языками, которую мы собираем сами по кускам. Скорость, цена хостинга, российские оплаты, заявки и перенос с Тильды остаются за Astro + Preact + нашей админкой. Брать Payload стоит не вместо, а рядом: как хранилище контента для одного-двух клиентов-«писателей», а витрина остаётся на Astro. Проба – около 18 ч, адаптер завода «статья → Payload черновиком» – около 7 ч, и делать его есть смысл только под живого клиента.

**Нужно от тебя:** (1) да или нет на пробу «Payload + Astro» на одном сайте, 18 ч ≈ 18 000 ₽ себестоимости по нашему часу 1000 ₽; (2) если да – какой клиент хочет сам писать и править много (статьи, новости, товары, несколько сотрудников в админке). Нет такого клиента – пробу не делаем, а адаптер Payload кладём в техдолг рядом с WordPress, Битриксом и Тильдой (задача №19 от 17.11).

## Payload – это готовая админка с базой и API, которую мы сейчас собираем сами по кускам

**Что это.** Открытая система управления контентом на TypeScript, лицензия MIT. С версии 3 ставится прямо внутрь проекта Next.js: в коде описываешь коллекции (Статьи, Товары, Заявки, Медиа), а Payload сам даёт базу, админку и API. Цифры на 17.11.2026: версия 3.93.0 от 04.11.2026 (npm), 45 865 звёзд на GitHub, 1,55 млн скачиваний за неделю 10–16.11 (api.npmjs.org). Требует Node 22.23+ или 24.22+ и Next.js 15.2.9+ или 16.3.3+ (зависимости пакета @payloadcms/next 3.93.0).

**Что внутри из коробки** (сверено по пакетам npm 17.11, все версии 3.93.0):

| Возможность | Как у Payload |
|---|---|
| База | Postgres, MongoDB, SQLite, Cloudflare D1 – адаптеры db-* |
| Админка | собирается по схеме коллекций; русский язык есть (пакет translations, файл ru) |
| Права | функции доступа на коллекцию, документ и поле; пользователи и API-ключи |
| Черновики и версии | черновик, автосохранение, отложенная публикация, статусы «Черновик / Опубликовано / Изменено», откат к опубликованному ([docs](https://payloadcms.com/docs/versions/drafts)) |
| Согласование | своего процесса нет: только права «редактор не публикует»; «Publishing Workflows» – в Enterprise |
| Медиа | загрузка, нарезка размеров, фокус-точка, кроп, перевод формата через sharp (formatOptions), хранение в S3 ([docs](https://payloadcms.com/docs/upload/overview)) |
| Языки | локализация полей и документов |
| Предпросмотр | Live Preview: черновик виден на сайте до публикации |
| API | REST, GraphQL и Local API – вызов из своего кода без сети |
| Хуки и задачи | хуки до и после сохранения, очередь задач (Jobs) |
| Официальные плагины | SEO, конструктор форм, редиректы, поиск, вложенные страницы, магазин, мультисайт, импорт-экспорт CSV, MCP для агентов |

**Payload 4.0 – бета с 19.10.2026** (сейчас 4.0.0-beta.9): движок отвязывают от Next.js через адаптеры, первый – TanStack Start; админка перерисована на дизайн-системе Figma; появилась медиатека с сеткой, превью PDF и видео; MCP включён по умолчанию, в коде есть «skills» для кодинг-агентов ([анонс Payload](https://payloadcms.com/posts/releases/payload-4-beta-redesigned-admin-tanstack-mcp)). Дата стабильного выпуска не названа.

**Кто купил и что это значит.** Figma купила Payload 17.06.2025, вся команда перешла в Figma, сумма не раскрыта ([страница Payload](https://payloadcms.com/payload-has-joined-figma), [Syntax.fm 17.06.2025](https://syntax.fm/show/912/why-did-figma-buy-a-cms/transcript)). Что из этого следует:

- **Плюс:** у проекта есть деньги и команда, ядро остаётся открытым: «Figma is committed to maintaining and investing in Payload's open source core».
- **Минус для нас:** облако Payload Cloud новые проекты не принимает («deployment of new projects is currently paused»), ставить можно только на свой сервер.
- **Куда идёт Figma:** 15.10.2026 Payload встроили в Figma Make как бэкенд для собранных там сайтов – база, файлы, вход, админка; хостинг в бете бесплатный, цены объявят позже ([блог Figma](https://www.figma.com/blog/websites-with-payload-in-figma/)). Нам это не опора: Figma ограничила работу с Россией в 2022 году (общеизвестно, сегодня не перепроверял), а вот самостоятельная установка MIT-версии от Figma не зависит.

**У Васина** Payload – одна строка в системе 06 «Публикация и индексация», рядом с файлом в репозиторий Next.js, WordPress по REST и Битриксом. Подробностей, как устроен его адаптер, на странице нет (текст страницы Цеха, снят 17.11).

## По функционалу Payload сильнее в редакторе и данных, мы – в скорости, цене, оплатах РФ и заявках

Наш стек – Astro для сайтов, Preact для островов и анимаций, админка по скиллу admin-builder с эталонов Elite Rose и EV, редактор site-editor, магазин shop-modules. На 17.11.2026 в ~/Sites 29 проектов на Astro, ни одного на Next.js или Payload (поиск по package.json).

## В заводе Payload – отдельный адаптер выкладки: клиент правит сам, но доказать «вышло» сложнее

Сейчас станция 7 (engine/vykladka.py) умеет только git-сайт: кладёт файл статьи в папку блога, делает свой коммит, запускает команду выкладки, проверяет живой адрес (200 и title) и откатывает только свой коммит при сбое. Адаптер Payload встаёт рядом, не вместо:

**Плюсы против git-выкладки:**

- Клиент сам правит статью в привычной админке, без нашего коммита и без письма «поменяйте абзац».
- Если сайт на Next.js – правка видна сразу, без пересборки. Если витрина на Astro – пересборка по хуку, но без git и без нас.
- Один адаптер подходит любому клиенту на Payload, как WordPress по REST.

**Минусы:**

- Доказательство «вышло» уходит из наших рук: ответ CMS – только «черновик принят», а публикует клиент. Нужен хук обратно в завод, иначе статья зависнет черновиком, а отчёт покажет «выложено».
- Клиент может испортить статью после гейтов: удалить ответ из первых 40–60 слов, ключи, ссылки. Сторож должен перепроверять живую страницу, а не наш файл.
- Схема коллекции у каждого клиента своя: поля и блоки надо сопоставлять при подключении.
- Откат «своего коммита» не работает: откатом становится версия в Payload.
- Сегодня это код без клиентов: у нас 0 сайтов на Payload.

**Оценка адаптера:** 3 ч – запись черновика с обложкой, SEO-полями и Markdown → Lexical; 2 ч – хук публикации, проверка живого адреса и IndexNow; 2 ч – тесты на поддельном Payload и проба на настоящем стенде. Итого 7 ч. С общим слоем адаптеров под WordPress, Битрикс и Тильду (задача №19) – около 10 ч.

## Брать Payload стоит только рядом с Astro и только под клиента, который сам ведёт много контента

| Тип проекта | Что ставим | Почему |
|---|---|---|
| Лендинг, визитка, клип-лендинг | Astro + site-editor | Правка кликом на странице, скорость, бесплатный хостинг |
| Магазин в РФ | Astro + shop-modules + каталог Elite Rose | Оплаты банков РФ, СДЭК, бонусы; у Payload только Stripe |
| Сайт с SEO-ведением и заводом | Astro + git-выкладка | Мы держим качество статьи до и после выхода |
| Клиент сам пишет новости, статьи, ведёт каталог, несколько сотрудников с ролями | **Payload как хранилище + Astro как витрина** | Готовые черновики, версии, медиатека, роли, без пересборки нами |
| Сайт уже на Next.js у клиента | Payload целиком | Встаёт в его же проект |

**Проба «Payload + Astro» на одном сайте – около 18 ч:**

- 4 ч – Payload 3.93 в Docker с Postgres на нашем FirstVDS, SSL, ночной бэкап, вход СВЕРХ админа;
- 5 ч – коллекции Страницы, Статьи, Медиа (WebP), Заявки, плагины SEO и редиректов, русская админка;
- 6 ч – Astro берёт контент по REST при сборке, хук «опубликовано» запускает пересборку, предпросмотр черновика;
- 3 ч – роли клиента, закрыть лишнее в API, порядок обновлений, короткая инструкция клиенту.

Сайт целиком на Next.js вместо Astro – ещё 12–16 ч на переписывание вёрстки, и скорость хуже: не советую. Ветку 4.0 на пробу не берём, пока она бета.

**Риски, которые надо принять до пробы:** обновлять Payload каждые 1–2 недели (54 бюллетеня за 2026); отдельный сервер и база на клиента; будущее облака решает Figma; v4 поменяет админку и часть настроек.

**Что раскрыть:** 1 – как Astro забирает контент из Payload и сколько ждать пересборки; 2 – адаптер завода по шагам и что видит клиент; 3 – сравнить Payload с нашим site-editor уровня 2–4 по часам; 4 – Payload Cloud и Figma Make: можно ли этим пользоваться из России.

### Что не подтвердилось или не проверено

- Один блог называл датой покупки 10.04.2026 – неверно: официально 17.06.2025.
- 2FA у Payload в коробке не нашёл – возможно, есть плагином сообщества, не проверял.
- Ограничения Figma для России – известно с 2022, сегодня не перепроверял.
- Сколько памяти ест Payload на сервере – не мерил, будет видно на пробе.
- Что Next.js «уходит» из Payload – неверно для 3.x: адаптеры другого движка только в бете 4.0, админка пока живёт в Next.js.
- Как устроен Payload-адаптер у Васина – на его странице только название.
